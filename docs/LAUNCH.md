# GitHub launch kit

## Repository description

Travel between two versions of your website. Local screenshots, an interactive before/after slider, and one offline HTML report.

## Upload from the GitHub website

1. Create a repository called `dev-time-machine` on your account. Choose Public if you want people to discover and star it.
2. Extract the ZIP and open the `dev-time-machine` folder.
3. Upload its contents to the repository, preserving the `bin`, `src`, `test`, `docs` and `.github` folders. Do not upload the ZIP itself as source code.
4. Make sure `.gitignore` and `.github/workflows/test.yml` are included; some file pickers hide dot-prefixed paths.
5. Add the description and topics below.

The `preview.html` file in the archive is an immediately viewable demo. It is also suitable as a public GitHub Pages demo if you choose to enable hosting later.

## Launch post

I built DevTimeMachine because I kept asking “did this UI look better before?”

It captures two versions of a website and turns them into a before/after slider. The report is one HTML file with embedded screenshots, so you can open it offline or send it to a teammate.

No account, no API key. The built-in demo runs without installing dependencies.

The first version is intentionally small: viewport screenshots and visual comparison. I'd love feedback on the workflow and what would make it useful in your projects.

Add your repository URL here after publishing.

## Before publishing

- Set a real repository description and the suggested topics.
- Keep `docs/preview.png` in the repository so the README preview renders.
- Do not commit `.time-machine/`, credentials or private screenshots.
- Add the public demo to GitHub Pages only if you want it hosted.
- Share in relevant communities according to their rules; do not buy stars or spam.
